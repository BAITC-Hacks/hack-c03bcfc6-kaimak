# Аким на 5 часов

Учебный AI-симулятор управления условным городом для первого задания HackAlem AI. Команда распределяет одинаковый стартовый бюджет **1 000 виртуальных млн ₸**: выбирает по одному мероприятию в транспорте, озеленении, социальной инфраструктуре, безопасности и городских сервисах, а также район для каждого мероприятия.

## Запуск

Нужен Python 3.10 или новее. Сторонние пакеты не требуются.

```bash
python3 server.py
```

Откройте `http://127.0.0.1:8000`. Для доступа с другого компьютера в сети можно задать `HOST=0.0.0.0` и `PORT`.

### Анализ OpenAI и NVIDIA

Сервер автоматически читает `OPENAI_API_KEY` и `NVIDIA_API_KEY` из файла `.env` в корне проекта. Формат без секретов есть в [`.env.example`](.env.example). Также можно задать ключи как переменные окружения. Не добавляйте реальные значения ключей в исходный код или документацию. Файл `.env` исключён из Git. Запросы к провайдерам отправляются только после нажатия «Получить AI-разбор» и содержат синтетические данные сценария без имени команды.

```bash
python3 server.py
```

NVIDIA NIM (`NVIDIA_MODEL`, по умолчанию `mistralai/mistral-nemotron`) предлагает независимую гипотезу о рисках распределения бюджета и районного неравенства через [Chat Completions API](https://docs.api.nvidia.com/nim/reference/mistralai-mistral-nemotron-infer). Затем OpenAI (`OPENAI_MODEL`, по умолчанию `gpt-4.1-mini`) пишет краткое объяснение для команды через [Responses API](https://developers.openai.com/api/docs/models/gpt-4.1-mini), учитывая проверенные результаты и замечание NVIDIA как гипотезу. Это разные задачи: оценка риска и понятный итоговый текст.

Если один сервис недоступен, другой продолжает работать. При ошибке обоих остаются локальные объяснение и рекомендация. API не меняют бюджет, последствия мероприятий или Score. Интерфейс показывает, какие провайдеры ответили. Ключи остаются на сервере; значения не выводятся в ответы и журналы.

Если NVIDIA возвращает `401`, сервер покажет ошибку авторизации вместо общего сообщения «ответ не получен». Проверьте ключ и доступ к публичным вызовам в [NVIDIA Build](https://build.nvidia.com/settings/api-keys). Возможна ситуация, когда `GET /v1/models` работает, а `POST /v1/chat/completions` отклоняется; это не исправляется заменой мероприятия или района в симуляторе. Для диагностики не отправляйте ключ в переписку и не добавляйте его в журналы.

## Основной сценарий

1. Изучите исходные показатели четырёх условных районов.
2. Выберите мероприятие и район в каждом из пяти направлений. Кнопка «Пример сценария» заполняет все пять решений.
3. Следите за общим бюджетом и предварительным Score. Интерфейс и сервер отклоняют превышение.
4. Нажмите «Получить AI-разбор» и посмотрите сильные стороны, риски, последствия и найденную альтернативу.
5. Сохраните сценарий под именем команды, сравните его с другими вариантами и откройте любой сохранённый набор решений. Сравнение хранится в `localStorage` этого браузера.

## Как считается Score

Все исходные данные в [`data.py`](data.py) синтетические; они не описывают реальные районы Астаны. Пять показателей заданы по шкале 0–100, где больше означает лучше. Имена районов условные.

Каждое мероприятие повышает свой основной показатель в выбранном районе на `impact × (1 + (100 − исходный показатель) / 250)`. Остальные районы получают 18% этого эффекта. Явно указанные в каталоге небольшие перекрёстные эффекты прибавляются к связанным показателям. Результат каждого показателя ограничен 100.

Показатель города по направлению — среднее районов с весом населения. Итоговый **Astana Quality of Life Score**:

```text
0.8 × взвешенная сумма пяти городских показателей
+ 0.2 × показатель самого слабого района
```

Веса направлений: транспорт 0.23, озеленение 0.18, социальная инфраструктура 0.23, безопасность 0.19, городской сервис 0.17. Районный показатель использует те же веса. Так слабый район влияет на результат, даже если инвестиции в более населённый район дают высокий средний эффект. Это прозрачная игровая модель, а не официальный индекс или прогноз.

## AI-анализ и архитектура

- [`engine.py`](engine.py) валидирует решения, считает последствия, объясняет наиболее значимые изменения и риски. Агент рекомендаций перебирает все допустимые замены одного мероприятия или района и предлагает лучший вариант, который улучшает Score без выхода за бюджет.
- [`server.py`](server.py) предоставляет `GET /api/bootstrap`, `POST /api/simulate` и `POST /api/analyze`. Оба POST принимают `{"choices": {"transport": {"action": "bus", "district": "north"}, ...}}`. Для анализа обязательны все пять направлений.
- [`static/app.js`](static/app.js) управляет интерфейсом, визуализацией и локальным сравнением команд. Сервер заново проверяет все цены, связи мероприятия с направлением, районы и общий бюджет; клиентские данные ему не доверяются.
- [`ai.py`](ai.py) загружает настройки из `.env`, формирует один набор проверенных фактов, вызывает NVIDIA для гипотезы о риске и OpenAI для итогового текста. Ответы провайдеров показываются отдельно от расчётных результатов. Числа остаются под контролем [`engine.py`](engine.py).

## Ограничения и развитие

Цены, эффекты и районные показатели намеренно вымышлены. Для применения к реальному планированию понадобятся проверенные данные, калибровка влияний, неопределённость прогноза и участие профильных экспертов. Командные сценарии сейчас сохраняются в одном браузере; общий рейтинг потребует серверного хранилища и идентификации команд.
